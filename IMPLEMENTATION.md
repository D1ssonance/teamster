## Quick Start

### 1. Generate Session Router

```bash
python3 session_router_generator.py \
  --reference reference-router.json \
  --output session-router.json
```

### 2. Use Router in Your Code

```python
from router_core import AgentRouter

# Initialize router
router = AgentRouter("session-router.json")

# Spawn agent with fallback
try:
    result = await router.spawn_agent(
        role="scout",
        task="Find all API endpoints",
        context="Repository analysis"
    )
    print(f"Spawned with model: {result['model']}")
except Exception as e:
    print(f"All fallbacks exhausted: {e}")
```

### 3. Monitor State

```bash
# View current cooldowns and quota usage
cat ~/.router-state.json | jq .
```

## Architecture

This implementation follows the two-tier architecture described in ARCHITECTURE.md:

1. **Reference Router** (reference-router.json)
   - Static, version-controlled configuration
   - Defines all roles, models, quota groups
   - Shared across sessions

2. **Session Router** (generated)
   - Filtered through model catalog availability
   - Per-session customization
   - Generated by session_router_generator.py

## State Management

Router state is persisted to `~/.router-state.json`:

```json
{
  "cooldowns": {
    "devx/model-a": {
      "until": 1704672000,
      "reason": "Rate limit exceeded"
    }
  },
  "starts": {
    "standard": [1704671940, 1704671950]
  }
}
```

State updates are:
- **Thread-safe** via file locking (fcntl.LOCK_EX)
- **Atomic** via write-to-temp + fsync + rename
- **Automatic** cleanup of expired cooldowns

## Integration with Your System

To integrate this router into your agent orchestration system:

1. **Replace stub `_spawn_with_provider()`** in router_core.py with your actual provider API calls
2. **Configure quota groups** in reference-router.json to match your rate limits
3. **Add model catalog** filtering if you maintain a dynamic model registry
4. **Customize error classification** patterns for your specific provider errors
